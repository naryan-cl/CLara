# User follow-up interview guide

Use these three short interviews to turn vague feedback into actionable product decisions. Each session should take about 20 minutes.

## Interview 1 — Where did you get stuck?

**Goal:** Replace “the function was not intuitive” with specific flows.

1. Walk me through the last time you used CLara. What were you trying to do?
2. Where did you pause, ask for help, or give up?
3. Which screen were you on (Dashboard, Add → Session, Reflect, Commons, Ask, Top 10)?
4. If you could change one button or label, what would it be?

**Capture:** Screen name, task, verbatim quote, severity (blocked / annoyed / minor).

## Interview 2 — Use cases and “hosting in one place”

**Goal:** Prioritize use-case presets and integration scope.

1. What are your top three jobs CLara should do perfectly for Camp CLAI?
2. After a session ends, what do you do with the output today (NotebookLM, Slack, docs, nothing)?
3. If CLara could open from one other tool, which would it be?
4. Would you rather merge **audio files** or get one **written report** from several sessions?

**Capture:** Ranked use cases, external tool name, merge vs report preference.

## Interview 3 — Naming, persona, and “flattening”

**Goal:** Clarify branding and anti-flattening preferences.

1. Show **structured export** vs **Top 10** — which feels less “flat”? Why?
2. Does “CLara” work for both Reflect and Ask, or would different names help?
3. What tone should the AI use (coach, peer, facilitator, neutral)?
4. When you said data felt “flattened,” which output were you looking at (export, Top 10, session Summary, Ask answer)?

**Capture:** Preferred surface, naming notes, persona tone, example artifact.

## After interviews

- Log decisions in `dev-plan-v0.3.md` §4 Progress & Decisions.
- Only build vague items after at least two participants name the same pain point.
